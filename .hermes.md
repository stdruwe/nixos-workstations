# NixOS System Configuration

This repository contains the canonical declarative NixOS system configuration.

## Current state

Before proposing or making persistent changes, read `CURRENT-STATE.md` and keep
it synchronized with durable architecture, profile or workflow changes.

## Location and model

- canonical installed path: `/etc/nixos`
- intended public repository: `stdruwe/nixos-workstations`
- matching public Home Manager repository: `stdruwe/home-manager-workstations`
- main entry point: `/etc/nixos/configuration.nix`
- local hardware selector: `/etc/nixos/profile.nix`
- local machine/user identity: `/etc/nixos/identity.json`
- optional local deployment infrastructure and Topgrade policy: `/etc/nixos/deployment.json`
- machine-local managed dependency state: `/etc/nixos/.local-sources/`
- traditional NixOS configuration; this repository is not a NixOS flake
- public version history starts at `v0.1.0`

Do not add `flake.nix` or convert the system repository to flakes unless
explicitly requested.

Tracked `lon.nix`, `lon.lock` and `pkgs/filebot-source.nix` are
clean-checkout/install bootstrap state. Installed machines use ignored
`.local-sources/` copies after Topgrade initializes them. Normal dependency
refreshes must not modify or publish the tracked bootstrap files.

## Repository structure

Keep the root reserved for primary entry points and repository-wide state.

- `hosts/<technical-profile>/` — hardware-specific configuration
- `modules/common/` — shared desktop-neutral modules
- `modules/desktops/` — explicit desktop environments
- `modules/features/` — reusable optional features
- `pkgs/` — local package definitions
- `scripts/` — support/maintenance helpers
- `docs/` — operational documentation

`install.sh` is the canonical profile-selecting user entry point. The three
hardware-specific install scripts intentionally remain in the root because they
contain device-specific safety logic:

- `install-thinkpad-x1-carbon-gen13.sh`
- `install-hp-z2-tower-g9.sh`
- `install-apple-macbook-air-8-1.sh`

Do not create a second dispatcher or move ordinary shared modules back into the
root.

## Hardware profiles and desktops

Hardware profiles are stable technical names and must not be renamed merely
because a hostname or username changes.

- `hosts/thinkpad-x1-carbon-gen13/default.nix` — KDE Plasma
- `hosts/hp-z2-tower-g9/default.nix` — KDE Plasma
- `hosts/apple-macbook-air-8-1/default.nix` — COSMIC

ThinkPad and HP use Disko plus Lanzaboote/Secure Boot/TPM2. The MacBook profile
has a separate explicit T2 dual-boot/storage model and systemd-boot without
EFI-NVRAM writes.

`configuration.nix` imports only ignored local `profile.nix`. The selected
profile imports `modules/common/identity.nix`, which reads ignored local
`identity.json`. `modules/common/deployment.nix` separately reads optional
ignored `deployment.json`; the configuration must remain valid when this file
is absent.

Desktop-neutral defaults belong under `modules/common/`. Desktop-specific
behavior belongs under `modules/desktops/`. Hardware-specific behavior belongs
under `hosts/<technical-profile>/`. Deployment-specific addresses, SSH host
keys, authorization keys and service endpoints belong in ignored
`deployment.json`.

Documentation must use technical profile names, hardware descriptions,
`<hostname>` and `<user>` placeholders rather than deployment-specific hostnames,
addresses or personal usernames unless a concrete runtime value is technically
required.

## Installation workflow

The preferred fresh-install route is the versioned combined install package
documented in `docs/install-package.md`.

Stable public releases use the same tag in NixOS and Home Manager. The public
release series starts at `v0.1.0`.

Before destructive disk confirmation, the installer validates Home Manager,
creates local identity/profile data, downloads the shared wallpaper, prepares
Apple fonts, and evaluates the selected NixOS profile. The ThinkPad installer
also generates the complete local EasyEffects tuning set before destructive
confirmation.

Home Manager's activation closure is built into the target store during
installation. `modules/common/home-manager-initial.nix` activates the prepared
closure before the first display-manager login.

Direct hardware-installer execution remains valid for development/recovery when
the required local Home Manager bundle is available.

Before modifying an installer, read the installer, `scripts/install-common.sh`,
and the corresponding `hosts/<technical-profile>/` files.

## MacBook profile invariants

Preserve these unless a new model-specific fix has been verified:

- `boot.loader.efi.canTouchEfiVariables = false`
- `pm_async=off`
- the profile-specific brcmfmac NDOE patch
- WLAN power saving remains enabled
- internal T2 NCM remains excluded from NetworkManager auto-profile creation by MAC
- optional deployment-specific `ssh-ng` remote builder; local builds remain allowed
- validated five-second Plymouth quit delay before COSMIC
- p1 Apple EFI and p2 macOS/APFS are protected and must never be changed by the NixOS workflow

Read `docs/apple-macbook-air-8-1-install.md` before storage/install changes.

## Fonts

Shared font policy lives in `modules/common/fonts.nix`; Gecko defaults live in
`modules/common/programs.nix`.

SF Pro, SF Mono and New York are downloaded from Apple's official Developer CDN
and placed under ignored `fonts/apple/`. Refresh them with
`/etc/nixos/scripts/update-apple-fonts.sh`. Do not commit the Apple font payload.

## Local generated/downloaded material

Do not commit local vendor or third-party payloads merely because a configured
machine needs them:

- shared wallpaper is fetched from KDE Store content `1189184` into ignored `assets/local/`
- Apple/HP/ThinkPad Plymouth vendor logos live under ignored `assets/local/`
- generated device-specific ThinkPad EasyEffects preset/IRS data lives under ignored `audio/easyeffects/local/`
- optional user-adjusted `Dolby-Dynamic-Balanced.json` lives under ignored `audio/easyeffects/local/override/`
- machine-local managed source pins live under ignored `.local-sources/`

The installer should acquire/generate required local data during non-destructive
preflight whenever practical. Clean checkouts must remain buildable without
optional local assets.

See `docs/third-party-material.md` before changing provenance or licensing
claims. That document describes the current repository model.

## Repository permissions and secrets

`/etc/nixos` remains `root:wheel` with group-write/setgid/ACL handling. Private
keys, tokens, passwords, agent sockets, `profile.nix`, `identity.json`,
`deployment.json`, `.local-sources/`, downloaded Apple fonts, local wallpaper,
local vendor logos and locally generated tuning remain outside Git/Nix store as
appropriate.

Shared sudo authentication timeout is 15 minutes.

Do not claim authorship merely because a file is tracked. Preserve explicit
upstream provenance/license context for third-party material. A repository-wide
license must not purport to relicense material outside the repository owner's
rights.

## Topgrade

Topgrade is the central manual update workflow for each installed machine.

Normal operation:

1. pull `/etc/nixos` and Home Manager from their configured upstreams using fast-forward-only Git pulls;
2. ensure ignored machine-local NixOS source copies and Home Manager `flake.lock` exist from tracked bootstrap states;
3. optionally advance only the current machine's managed dependencies;
4. validate candidate NixOS source state against only the current hardware profile;
5. validate candidate Home Manager lock against only the current Home Manager profile;
6. retain candidates only after successful validation;
7. perform guarded NixOS activation and normal Home Manager/other updates.

`topgrade.updateManagedDependencies = false` freezes machine-local managed
dependency advancement without disabling repository synchronization or normal
activation.

Never introduce publisher profiles, automatic dependency commits, automatic
dependency pushes, cross-machine transactions or cross-profile dependency
validation. A consumer of a public repository must not need write permission to
its upstream.

Topgrade-owned messages and subprocess messages are requested in English. Locale
configuration may remain German where intentionally configured.

When checking package versions, compare the configured `nixos-unstable` channel
with `nixos-unstable`, never nixpkgs `master`.

## Working rules

1. Read `CURRENT-STATE.md` first.
2. Inspect relevant existing modules before editing.
3. Preserve hardware-profile/identity/deployment separation.
4. Keep shared desktop-neutral modules in `modules/common/`.
5. Keep desktop-specific modules in `modules/desktops/`.
6. Keep reusable optional modules in `modules/features/`.
7. Keep hardware-specific configuration under `hosts/<technical-profile>/`.
8. Keep support scripts under `scripts/` unless they are deliberate root entry points.
9. Keep machine/user identity in ignored local files.
10. Keep deployment-specific infrastructure in ignored `deployment.json`.
11. Prefer declarative NixOS configuration over imperative changes.
12. Do not duplicate settings already implemented elsewhere.
13. Do not edit tracked generated `lon.nix` merely to advance an installed machine.
14. Do not expose secrets or place credentials in the Nix store.
15. Check whether user-level behavior belongs in the separate Home Manager repository.
16. Do not run destructive commands without explicit approval.
17. Do not infer authorship or licensing status from repository presence alone.
18. Do not make normal Topgrade operation depend on upstream Git write access.
19. Do not store shared wallpaper or device-specific ThinkPad tuning in Git.
20. Keep public documentation focused on the current repository state.

For persistent installed-system activation, use:

```bash
sudo nixos-rebuild switch
```

On the MacBook profile, do not routinely add a preceding full
`nixos-rebuild build`; `switch` already builds the target and expensive work may
be delegated when local deployment data configures a remote builder.
